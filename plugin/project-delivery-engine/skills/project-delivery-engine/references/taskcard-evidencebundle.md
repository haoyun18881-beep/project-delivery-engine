# TaskCard 与 EvidenceBundle

本文件是正式协作节点的任务与返回协议。承担文件、代码或产物写入（含隔离写入）、独立复审，或结果将进入项目持久治理记录的节点必须使用完整格式；简单只读协作沿用宿主原生任务合同，但仍须明确目标和读取范围，并返回证据、风险和未覆盖项。

## TaskCard

```text
run_id（执行批次编号）：
task_id（任务编号）：
parent_task_id（父任务编号，可选）：
目标：
读取范围：
写入范围：
禁止事项：
验收要求：
预期证据形态（可选）：
artifact（产物声明；产生或修改文件时必填，纯只读可省略）：
确认闸门（仅当前规则要求确认时填写）：
停止条件：
```

- 正式协议中的 `run_id` 关联同一批任务；`task_id` 在批次内唯一。
- 范围必须具体；只读任务的写入范围写 `none`。
- 任务卡应自包含，不要求协作线程猜测父线程上下文。
- 可在宿主派遣消息和返回结果中承载完整协议，复用能满足唯一性与关联要求的原生编号；不因使用正式协议而额外创建任务卡或证据包文件。只有确有持久保存需要时才落盘，并沿用已有入口。
- 产生或修改文件、代码、落盘报告或索引时，必须填写 `artifact（产物声明）`，列明预期产物和路径。
- 纯只读且不产生上述产物的简单任务可省略 `artifact（产物声明）`。
- `确认闸门` 只在当前适用规则确实要求尚未取得的确认时填写；承接当前会话和任务范围内的已有有效授权，不得让普通低风险任务增加确认负担。
- `预期证据形态` 写明验收依赖的观察信号形态（如错误响应格式、错误文本差异、时序行为），而非仅状态码或通过/失败；EvidenceBundle 的 `实际检查` 必须记录观察到的差异信号，不得只记录通过/失败。

## EvidenceBundle

```text
run_id：
task_id：
结果：
实际检查：
改动文件：
验证：
风险与未覆盖项：
```

- `run_id + task_id` 必须与 TaskCard 一致。
- 只记录真实检查、真实改动和真实验证；未执行的项目写明原因。
- 长输出只返回必要短摘录和可定位锚点。
- 使用 worktree 时，子任务补充实际路径、基线和改动。采纳与清理由主线程在回收后另行记录。
