# 协作治理边界

本文件只在宿主已经采用协作、独立复审或隔离写入时读取；它约束结果治理，不决定是否派遣、并行或选择隔离方式。

## 授权

是否可自主使用协作、并行、worktree 和派生树，按用户意图、已有有效授权及宿主运行约束判断。已有授权包括当前会话已授予的授权、适用的常驻授权，以及任务范围内合理包含的常规操作；进入本 Skill 不重新索要已有授权。净收益为正、范围和验收清楚时可在授权内直接使用；超出范围或确需用户裁决时再确认。只有用户指令或当前规则已授权自动回收时，满足下述回收条件的当前智能体临时 worktree 才能自动清理。

## 任务组织

正式 TaskCard / EvidenceBundle 用于承担文件、代码或产物写入（含隔离写入）、独立复审，或结果将进入项目持久治理记录的协作节点。简单只读协作沿用宿主原生任务合同，不要求补造 `run_id`、`task_id` 或 `artifact`；任务仍须明确目标和读取范围，返回时仍须给出证据、风险和未覆盖项。

* 需要正式协议的单个协作节点使用一张 TaskCard（任务卡）。
* 有依赖的节点不得提前执行；同一文件或生成物不得无隔离地并行写入。
* 用户并发修改、基线漂移或未声明共享写入出现时，停止受影响节点；独立节点可继续。
* 派遣方复核直接子代理的关键证据，复核深度与风险相称；多层委派不免除主线程对最终采纳与整体交付的责任。子代理报告自身任务完成，不代表项目或整体任务已经完成。

正式 TaskCard 和返回结果按 [taskcard-evidencebundle.md](taskcard-evidencebundle.md) 处理。

## 独立复审

* 只有状态变化无法从检查点、进度账和原始产物可靠重建，或用户明确要求时，才强制独立复审。其他任务仅在主线程判断存在需要独立证据才能关闭的重大风险时按需复审；任务较长、经过上下文压缩、使用多智能体、worktree 或产生 checkpoint，都不单独触发复审。
* 复审默认只读并使用独立上下文，只提供任务边界、原始产物、验收要求和必要证据，不预灌主线程结论。
* 复审按 TaskCard 和 EvidenceBundle 返回偏差、矛盾、遗漏及验证缺口；主线程负责裁决，严重问题未关闭不得宣布完成。
* 默认首审一次、修复后定向复核一次；达到停止条件即结束，禁止无边界递归审查。

## worktree

不得为了使用 worktree 初始化 Git。创建失败时停止该节点，不得静默改为共享写入。

任务结束后，主线程必须自行检查实际路径、基线、改动、未跟踪文件、验证、索引引用和运行中任务。已获自动回收授权的当前智能体临时 worktree，在采纳或丢弃已明确、唯一产物已保全、无未回收成果、无索引引用、无运行中任务且状态明确时必须自动清理。没有自动回收授权、任一条件无法确认、由用户创建或来源不明的 worktree 不得自动清理，只报告具体路径和原因并按确认边界处理。

## 上下文预算

搜索、网页、长文件、日志和批量命令应限制范围与输出，只回收结论、锚点和必要短摘录。代码和调试任务必须保留完整的读改测循环。
