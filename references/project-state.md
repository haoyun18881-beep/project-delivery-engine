# 项目状态、建档与交接

本文件只在任务需要判断或维护项目持久状态时读取，包括项目状态不清、新建或修复五件套、接续恢复、五层落层或 checkpoint（检查点）。

## 项目入口

五件套：

- `AGENTS.md`
- `PROJECT_START_HERE.md`
- `STATUS.md`
- `TODO.md`
- `HANDOFF.md`

最小索引：

- `历史记录/00-历史总目录.md`
- `证据库/总索引/证据总目录.md`
- `项目物料/INDEX.md`

机械检查和治理文件写入按 [project-gov-cli.md](project-gov-cli.md) 执行。

项目根以当前工作区或命令传入的 `--root` 为准，不要把某台机器的绝对路径写成永久身份。项目移动后使用新根目录；绑定旧绝对路径的编译计划应丢弃并重新预演。

## 读取顺序

接续项目时先读 `AGENTS.md`、`PROJECT_START_HERE.md`、`HANDOFF.md`、`STATUS.md`、`TODO.md` 的摘要、索引和结尾。只有当前任务需要时，才沿索引读取历史、证据、物料或专项文档；大文件先定位相关标题和锚点。

明确当前任务后，必须用任务涉及的对象、动作、风险和已有关键引用，与五件套和三个核心索引中的路径、摘要、用途做一次轻量相关性判断。用户只说“继续做”时，先从已保存的状态和下一步推断本轮任务，再做这项判断。只有某项既有项目知识可能改变本轮方案、边界或验收时，才读取最相关的权威入口及必要上下文；没有相关信号时静默继续，不递归展开目录，也不批量加载项目知识资产。

接续方不得重测 `## 已证伪路线` 中已登记的路线，除非该行复开条件已满足。

版本、环境、适用前提或新证据发生实质变化，可能影响原证伪结论时，先核实变化与该结论的关系；确有依据后，通过受控写入修订复开条件并保留原证伪证据和修订理由，再按更新后的条件决定是否重测。不得仅因换了对话、代理或思路就重开路线。

若 `STATUS.md` 或 `HANDOFF.md` 指向尚未收口的运行中进度账，读完五件套后只读其中的不可回退基线和未吸收尾部；已被正式 checkpoint 吸收的旧条目不重复加载。

## 新建与修复

缺什么补什么，坏什么修什么，不覆盖已有有效内容。新项目创建五件套和三个最小索引，不预建无内容的完整目录树。

旧项目首次接入、治理结构版本变化或出现结构缺损时，先运行 `project-gov migrate-check（迁移检查）`；已有当前结构的通过记录且无相关变化时，不因每次接续重复运行。它只报告机械差异和检查范围，不自动改写或生成迁移计划：缺少必需结构时做最小修补，保留有效内容和自定义列，不因升级强制生成可选章节。扫描不完整或记录覆盖关系未核对时，不得宣称迁移完成；治理写入仍须通过 `propose → apply` 的当次校验。

旧项目第一次按本版规则整理资料、整理交接或发生治理写入时，同时做一次有边界的项目知识复核：先看五件套、三个索引的路径与摘要，以及本轮命中的最相关权威入口；证据不足或冲突时按“读取顺序”定向补查。不得默认遍历全部历史、证据或物料，也不得把“复核”理解成必须回填知识；只有发现已经核实且以后会复用的内容时才创建或更新权威入口。

根目录旧编号文档、治理层空目录和旧缓存属于物理布局事实。新项目不主动制造这些内容；`migrate-check` 只浅层列出根目录编号文档，`prune` 只读盘点旧缓存，空目录和其他布局由主线程按需检查。工具不自动搬移或删除；需要迁移时必须保留可追溯入口，并把历史遗留与新建规则分开验收。

项目文件职责：

- `AGENTS.md`：项目身份、稳定事实、用户授权与边界，以及执行时需要的项目规则或其入口。
- `PROJECT_START_HERE.md`：项目根识别方式和启动入口；不保存绑定某台机器的固定绝对路径。
- `STATUS.md`：当前状态、验证和变量。
- `TODO.md`：下一步和待确认事项。
- `HANDOFF.md`：最后语义检查点、接手顺序、已证伪路线、关键索引和未决上下文。

模板见 [project-file-templates.md](project-file-templates.md)。

`README.md` 等概览文件保存项目介绍、安装使用、支持范围、必要限制和文档入口；公开版本与兼容信息应与实际产物一致。内部任务进度、下一步和交接事实以第 3 层为权威，不在概览文件重复维护。

物料索引的 `hash` 列只是声明；需要确认文件正文仍与声明一致时，运行 `project-gov verify-materials（核验物料）`。普通结构校验不会为了一个检查读取全部大型物料。

## 状态与验证的对应

影响项目基线、完成判断或重要风险的结论，必须能定位它所依据的实际产物、验证对象和证据。沿用当前“依据”“验证”或关键引用，按需写明文件及版本、文件指纹或其他足以区分产物的信息，并注明会影响判断的验证时间、环境和覆盖范围；不依赖 Git，也不要求给每条记录新增固定字段。对象或适用条件已经变化时，旧验证不得直接当作当前版本已通过。

按实际情况区分已实现、已验证、已采纳和已交付；候选产物存在不等于进入当前基线。未执行、受阻或未覆盖必须如实标注，预期结果不能写成验证结果。五件套、进度账与产物不一致时，先核对证据和未吸收进展，再更新受影响记录，不按时间较新或措辞更肯定的一方直接覆盖。

## 五层落层

| 层级 | 位置 | 内容 |
| --- | --- | --- |
| 第 1 层 | `AGENTS.md` | 稳定项目规则与发挥空间 |
| 第 2 层 | `PROJECT_START_HERE.md` | 启动入口 |
| 第 3 层 | `STATUS.md` / `TODO.md` / `HANDOFF.md` | 当前工作快照 |
| 第 4 层 | `历史记录/` / `证据库/` | 重要决策与证据摘要 |
| 第 5 层 | `项目物料/` | 真实文件、备份、原件、输出产物和需要单独索引的项目知识资产 |

源码、测试、正常配置和工程文档保留在项目原有目录，不为了治理落层迁入第 4/5 层。对这些文件的普通读改测不触发本 Skill、`propose → apply` 或 checkpoint；只有同时需要更新持久治理状态时，才另行处理受影响的治理文件。

项目知识资产是对现有权威文档和第 5 层的用途扩展，不是第 6 层，也不要求每个项目新建知识库。识别和沉淀规则见 [project-knowledge.md](project-knowledge.md)。

## 运行中轻量进度账

当执行过程存在实际的中断恢复、设计回退或上下文遗忘风险时，维护或复用一份项目内的运行中轻量进度账。多轮、多 Agent、多 worktree 或耗时较长是判断线索，不单独触发建账；已有记录足以恢复时复用，短任务和没有恢复风险的普通验证不另建。

- 优先复用当前 TaskCard（任务卡）、执行计划或工作台中的进度文件；没有合适入口时才创建一份简短 `PROGRESS.md`。进度账必须能从已有启动或交接入口定位：已有指针时不改三件套；缺少指针时，在首次落账时通过一次最小 checkpoint 补入，避免意外中断后找不到。此时记录的是交接入口的实质变化，之后的逐笔进度不反复改三件套。
- 文件顶部只保留当前不可回退基线，例如用户已定设计、仍打开的 Gate、候选不能冒充完成、禁止自动重试或不得越过的安全边界。除非用户新裁决或新证据已经推翻，后续工作不得静默改回旧方案。
- 只在出现可验证的状态变化时立刻记一笔：候选提交冻结、独立复审结论、Gate 变化、合并或拒收、活动 worktree 变化、用户裁决、阻塞解除或不可回退基线变化。普通命令、重复测试、“仍在运行”和轮询不记。
- 每笔保持一行或极短条目，至少包含时间、对象、状态变化、证据指针、下一步或阻塞，以及不可回退基线是“未变”还是“按何依据变化”。不复制长日志、完整 diff 或聊天流水。
- 进度账是阶段内恢复依据，不是正式当前状态、项目知识或证据库。对它的普通更新不运行 `project-gov`；不得借此绕过本来就需要授权、证据归档或正式治理写入的事项。

阶段/Gate 收口、切换主题、准备交接或任务结束时，只有仍有未吸收的持久状态、下一步或 Gate、重要风险或裁决、交接入口等实质变化，才用正式 checkpoint 汇总进受影响的三件套；没有这类变化时不为阶段结束机械改写三件套。写入时只保留短结论和进度账/证据入口，不把整份流水复制进去；随后在进度账标明已吸收截止点，下一阶段可复用同一文件或另开一份。

## checkpoint

只有未吸收的持久状态、下一步或 Gate、重要风险或裁决、交接入口发生实质变化时，才写 checkpoint。阶段/Gate 收口、切换主题、交接或任务结束是合适的写入时机，不是单独触发条件。长阶段内的中间候选和逐步进展先写运行中轻量进度账；但新事实若立即推翻当前安全边界、授权、已证伪路线或对外状态，必须在同一回合做正式 checkpoint。普通代码或文档修改、常规验证和只读检查不自动沉淀。

checkpoint 前同时判断本轮是否产生了以后可能复用的已验证经验。只有确有复用价值时才按 [project-knowledge.md](project-knowledge.md) 沉淀；这项判断不等于每轮都要新增知识文件。

本轮需要 `project-gov propose（预演）` 时，操作计划必须带临时 `knowledge_review（知识审查）` 声明。它随操作计划和编译计划按正常生命周期清理，不进入五件套或新增索引；状态与知识均未变化、无需治理写入时，不得为了留下声明制造空计划。

会被后续接续重复、且具有项目级复用价值的路线或假设被关闭时，才在同一回合登记 `HANDOFF.md` 的 `## 已证伪路线`。普通测试完成、一次性调试结果不进该表；旁证类观察（真实但不推进主线的结果）只写入 `STATUS.md` 验证表并将 `层级` 标注为 `旁证`。

只更新受影响的当前文件和 `HANDOFF.md` 的语义检查点，不按轮追加流水账。详细过程进入对应层，五件套只保留短结论和可追溯引用。

会变化的外部状态必须注明最后观察时间，不得把旧观察写成实时事实。

## 五件套体量

五件套合计不得超过 45 KiB（46,080 bytes）。`propose` 会内置同一套写前检查，无需为此预先单独运行 `inspect`；只在需要只读诊断或结构化报告时单独使用它。超限时先减少当前快照，并为迁出内容保留有效索引。剩余空间低于 2 KiB 时工具只发提醒，不阻断当前任务。

## 换新对话

项目可以仍有已知的未完成事项；生成启动语前，必须把这些事项、风险和当前基线如实对齐。状态存在无法解释的缺口时，不能改写为“已核对”，也不能提供替代启动语绕过下面的对账与机械校验门槛。

用户要求换新对话或生成启动语时，必须先完成语义对账：

1. 从 `HANDOFF.md` 的最后语义检查点开始，核对其后所有会改变状态、下一步、变量、重要裁决或交接事实的事件。
2. 更新受影响文件，对照 `STATUS.md`、`TODO.md`、`HANDOFF.md`，解决过期或冲突内容；不全量重读无关文档。
3. 更新 `HANDOFF.md` 的最后语义检查点和“检查点后变化”状态。

交接时若无法从 checkpoint、进度账和原始产物可靠重建检查点后的状态变化，例如压缩导致记录缺口，或跨过多个主题且记录不完整、相互冲突，必须独立只读复核。单纯发生过上下文压缩、任务较长、使用多智能体或已有 checkpoint，不会单独触发。无法确认的内容必须写成待确认；未完成对账不得宣布交接完成或生成启动语。

语义对账完成后直接运行 `project-gov startup`；它已内置机械校验，无需先单独运行 `validate`。机械校验失败时不得生成启动语。
